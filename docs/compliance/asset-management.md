## 1. 资产分类

### 1.1 信息资产

| 类别     | 资产示例                     | 责任人     | 存储位置           |
| -------- | ---------------------------- | ---------- | ------------------ |
| 用户数据 | 用户信息、组织信息、回测配置 | 技术负责人 | PostgreSQL         |
| 审计日志 | 操作日志、登录日志           | 安全负责人 | PostgreSQL + MinIO |
| 备份数据 | WAL 归档、全量备份           | 运维工程师 | MinIO / S3         |
| 源代码   | 前端/后端/引擎代码           | 技术负责人 | GitHub             |
| 配置文件 | K8s/Docker/CI 配置           | 运维工程师 | Git 仓库           |

### 1.2 物理资产（云厂商承担）

| 类别     | 资产示例             | 责任方 |
| -------- | -------------------- | ------ |
| 计算资源 | K8s 节点、负载均衡器 | 云厂商 |
| 存储资源 | 持久卷、对象存储     | 云厂商 |
| 网络资源 | VPC、安全组、CDN     | 云厂商 |

> 物理资产管理详见 `docs/compliance/physical-security.md`（责任共担模式）

## 2. 资产清单维护

### 2.1 软件资产清单

| 组件       | 版本      | 许可证             | 漏洞扫描                |
| ---------- | --------- | ------------------ | ----------------------- |
| Node.js    | 20 LTS    | MIT                | npm audit               |
| PostgreSQL | 16        | PostgreSQL License | govulncheck (Go client) |
| Go         | 1.22/1.23 | BSD-3-Clause       | govulncheck             |
| Redis      | 7         | BSD-3-Clause       | —                       |
| APISIX     | 3.11.0    | Apache-2.0         | —                       |

### 2.2 SBOM（软件物料清单）

CI 自动生成 CycloneDX SBOM（`docker` job），覆盖 3 个容器镜像：

- `backtest-api`（Node.js 后端）
- `engine-go`（Go 回测引擎）
- `data-fetcher`（Go 数据服务）

SBOM 制品保留 30 天，用于漏洞响应（快速定位受影响组件）。

---

## 3. 资产变更追踪

- 所有资产变更通过 Git PR + CI 审查
- 依赖升级须通过 `security-scan` job（npm audit + govulncheck）
- 镜像版本以 Git SHA 标记，可追溯
- 审计日志记录所有数据资产变更（写操作）

---

## 4. 资产处置

| 资产类型 | 处置方式                       | 验证                |
| -------- | ------------------------------ | ------------------- |
| 用户数据 | 软删除 30 天 → 硬删除          | `DELETE FROM users` |
| 审计日志 | MinIO Object Lock 到期自动删除 | 180 天后清理        |
| 备份数据 | WAL-G `delete retain 7`        | 保留 7 份全量       |
| 容器镜像 | GHCR 自动清理旧 tag            | 保留最近 10 版本    |
| K8s 资源 | `kubectl delete` + PV 清理     | 最终一致性验证      |
