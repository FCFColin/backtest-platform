# ADR-016: 移除零消费者认证与用户管理出口

| 状态 | 已接受 | 日期 | 2026-08-15 | 合并 | — | 关联 | ADR-007, ADR-012 |

## Context

收敛审计（决策原则：企业级实践 ∧ 行数便宜 ∧ 不牺牲功能/可读性）发现三处零生产消费者的认证/用户管理出口，仅测试引用，保留即多一份需维护的公开 API 面：

1. `handleApiKeyAuth`/`handleOptionalApiKey`（middleware/apiKeyAuth.ts）：仅转发到 `authenticateWithApiKey(req, res, next, optional)` 的薄包装，无路由挂载。
2. `verifyPayload`（middleware/auditMiddleware.ts）：`auditCrypto.verifyAuditEntry` 的导出别名，生产路径全部直用后者（auditStorageService 消费）。
3. `deleteUser`（repositories/userRepo.ts）：物理删除 users 行的仓库函数，零生产消费者；用户删除语义生产路径走 `anonymizeUser`（GDPR Art.17 匿名化）。

## Decision

- 删除以上导出；配套测试迁移到被包装的真实函数（`authenticateWithApiKey(..., optional)`、`verifyAuditEntry`）；`deleteUser`/`range` 测试随功能删除，其行为分别由 `anonymizeUser` 与 `numericRange` 的既有测试覆盖。
- 不改变任何鉴权/审计语义：删除后调用面等价于原包装直接指向的实现。

## Consequences

- (+) 消除重复公开出口，降低未来路由误挂可选鉴权包装的风险。
- (+) 用户删除统一走匿名化路径，避免物理删除绕过审计可追溯性（ADR-007 基线）。
- (-) 未来若需包装器或物理删除需按本 ADR 重新引入（成本显式可见）。
