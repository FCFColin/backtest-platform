# ADR-048: 退役零消费者子系统与死配置旋钮

| 状态 | 已接受 | 日期 | 2026-08-08 | 合并 | — | 关联 | ADR-014, ADR-017, ADR-032 |

## Context

全仓库收敛审计（决策原则：企业级实践 ∧ 行数便宜 ∧ 不牺牲功能/可读性）发现以下子系统自引入起零生产消费者或零实际校验，保留仅增加配置面与维护面：

1. **Unleash 功能开关**：`unleashClient` 及 `isEnabled`/`logFlagAccess`/`PLAN_LIMIT_FLAGS` 无任何调用方；前端无 flag 使用；仅 k8s 清单与文档提及。
2. **DB 化 RBAC 查询**：`requirePermissionFromDb`/`rbacRepo`/`rbacCache` 无路由调用——所有端点均走静态 `ROLE_PERMISSIONS` + JWT `org_role`（ADR-017/032），数据库路径从未生效。
3. **密码策略环境旋钮**：`PASSWORD_MIN_LENGTH` 等 4 项 env 从未接入任何校验逻辑，实际密码策略由 `registerSchema`（Zod，min 12）强制。
4. **`/data/manage/regenerate-meta` 假端点**：返回固定文案、无状态、无消费者。
5. **`BacktestCompleted` 事件双写**：`backtest-service` 在 outbox 写库外另走一次同步 `eventDispatcher.dispatch`，同一事件被处理两次。

## Decision

- 删除以上零消费者代码、配置、部署面与文档；相关依赖（unleash）卸载；配套测试迁移或随被删功能删除，不降低共享断言覆盖率。
- **密码策略改为真实校验**：`registerSchema.password` 由 `min(6)` 提升至 `min(12)`（原旋钮默认值），符合 NIST 800-63B 最小长度优先；无新增配置面。
- **RBAC 维持静态权限矩阵 + JWT `org_role` 优先**（ADR-017/032），保留 `user_roles`/`role_permissions` 表结构，未来按需以本 ADR 为基线恢复 DB 路径。
- **事件收敛为单一 outbox 路径**（ADR-014）：`BacktestCompleted` 仅经 `writeEventInTransaction` + `NOTIFY` 写入，由 outbox 消费者 dispatch 至 `BacktestCompletedHandler` 持久化 `backtest_runs`。
- 删除门禁按决策原则执行：确认零消费者、无悬挂配置面、测试迁移、本 ADR 独立记录。

## Consequences

- (+) 消除死配置面与重复事件路径，减少维护/误配风险；密码策略从"看似可配、实际未生效"变为真实强制。
- (+) 保持 outbox 可审计性（单一写入路径、幂等消费）。
- (-) 未来启用动态 RBAC 或功能开关需重新引入（以本 ADR 为基线，成本显式可见）。
