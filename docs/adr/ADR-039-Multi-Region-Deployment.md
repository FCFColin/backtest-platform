# ADR-039: 多区域部署策略

## Status
Proposed

## Date
2025-07-25

## Context
回测平台需要服务中国和海外用户：
- 中国用户：等保三级要求，数据不出境
- 海外用户：低延迟访问

当前单区域部署无法满足：
1. 合规要求：中国用户数据必须存储在中国境内
2. 性能要求：海外用户访问中国服务器延迟 >200ms
3. 灾备要求：单区域故障导致全量不可用

## Decision

### 双区域主从架构
| 区域 | 云厂商 | 位置 | 用途 |
|---|---|---|---|
| CN | 阿里云 | 华东2（上海） | 中国用户 + 主数据库 |
| SG | AWS | ap-southeast-1（新加坡） | 海外用户 |

### 数据驻留策略
- **用户数据**：各区域独立主库，不跨区域同步
- **市场数据**：双向同步 ticker 元数据（非用户数据，合规允许）
- **认证**：各区域独立 JWT 签发 + 独立用户池
- **计费**：各区域独立 Stripe 账户

### 实施阶段
1. **第一阶段（6 个月）**：CN 区域完整部署，验证生产稳定性
2. **第二阶段（12 个月）**：SG 区域部署 + GeoDNS 流量路由

### 流量路由
- GeoDNS 按用户地理位置路由到最近区域
- 中国大陆 IP → CN 区域
- 其他 → SG 区域
- 区域内故障 → 自动 fallback 到另一区域（仅限只读端点）

## Consequences
- 各区域独立部署，运维复杂度 ×2
- 市场数据双向同步需要冲突解决策略（最后写入优先）
- 用户跨区域迁移需要手动支持（不自动迁移）
- 成本增加约 60%（双区域基础设施）
