# ADR-012: 退役批次审计

| 状态 | 已接受 | 日期 | 2026-08-08~16 | 合并 | — | 关联 | ADR-002, ADR-003, ADR-005, ADR-007, ADR-009, ADR-010 |

> 本 ADR 合并原 ADR-012~018，统一记录全仓库收敛审计中发现并退役的零消费者子系统、死配置面、死 schema 与遗留脚本。各子项原 ADR 编号保留追溯。

## Context

全仓库收敛审计（决策原则：企业级实践 ∧ 行数便宜 ∧ 不牺牲功能/可读性）分多轮发现以下零消费者或零有效利用的对象，保留仅增加配置面、schema 面或维护面：

### ADR-012 — 零消费者子系统与死配置旋钮

1. **Unleash 功能开关**：`unleashClient` / `isEnabled` / `logFlagAccess` / `PLAN_LIMIT_FLAGS` 无任何调用方。
2. **DB 化 RBAC 查询**：`requirePermissionFromDb` / `rbacRepo` / `rbacCache` 无路由调用——所有端点走静态 `ROLE_PERMISSIONS` + JWT `org_role`（ADR-007/ADR-009）。
3. **密码策略环境旋钮**：`PASSWORD_MIN_LENGTH` 等 4 项 env 从未接入校验逻辑，实际由 `registerSchema`（Zod，min 12）强制。
4. **`/data/manage/regenerate-meta` 假端点**：返回固定文案、无状态、无消费者。
5. **`BacktestCompleted` 事件双写**：outbox 写库外另走同步 `eventDispatcher.dispatch`，同一事件被处理两次。
6. **quota 60s 窗口**：`enforceQuota` 的 Lua INCR+EXPIRE 60s 把月额度当 60s limit，与 `computeLimiter`（10 req/min）和 `getMonthlyUsage`（月度 gate）双重重叠。

### ADR-013 — 死 schema

7. **daily_aggregate / weekly_aggregate 连续聚合视图**：001 建立后零查询消费者。
8. **portfolios.visible_to_roles**：零代码读写——多租户经 `tenant_id` / memberships / RLS（ADR-009）。
9. **backtest_runs.queued**：应用层 `'queued'` 由 `STATUS_MAP` 映射为 `'pending'` 写入，DB 默认值从未生效。
10. **冗余索引**：`idx_backtest_runs_tenant` 被复合索引覆盖；`idx_users_mfa_enabled` 布尔低选择性部分索引无查询利用。
11. **prices `*_numeric` 列**：仅 data-fetcher 写入、零读取方；**org_memberships** 零生产消费者；**idx_ff_factors_date** 与主键索引重复；**prices_monthly** 缺 SELECT 授权。
12. **users.mfa_secret / mfa_backup_codes**：MFA/TOTP 未实施（保留未删，供未来恢复）。

### ADR-014 — 未实现引擎字段

13. **riskFreeRate**：前端接受但 Go 引擎不消费，Sharpe 计算硬编码 `engineutil.RiskFreeRate = 0.02`。
14. **withReplacement**：`monteCarloSchema.mcParams` 接受但 Go 引擎零匹配——block bootstrap 采样本身即带放回。

### ADR-015 — data-fetcher 独立 worker CLI

15. **`data-fetcher/cmd/worker`**（1,243 行）：零消费者——构建面无引用（`rg cmd/worker` 零命中）；更新作业已由 TS BullMQ worker 接管；数据获取由 HTTP 服务承担；SIM 拼接为平行的已淘汰实现；`package main` 不可导入。

### ADR-016 — 零消费者认证与用户管理出口

16. **`handleApiKeyAuth` / `handleOptionalApiKey`**：仅转发到 `authenticateWithApiKey` 的薄包装，无路由挂载。
17. **`verifyPayload`**：`verifyAuditEntry` 的导出别名，生产路径直用后者。
18. **`deleteUser`**：物理删除 users 行的仓库函数，零消费者——生产走 `anonymizeUser`（GDPR Art.17）。

### ADR-017 — 悬空 verify 脚本

19. **`verify-backend.mjs` / `verify-frontend.mjs`**（476 行）：CI 以 `--skip-db --skip-frontend` 跳过，nightly 未挂载；verify-frontend BASE 固定 `localhost:15173`（vite dev），历史上从未跑通。所有检查项已有更强替代（`check-migrations.mjs`、`rls-isolation.integration.test.ts`、E2E specs）。

### ADR-018 — 迁移回滚机制

20. **rollbackSchema + down 迁移**：行业实践均为 forward-only（drizzle/prisma/opencode）；down 迁移在实践中几乎不执行，随 schema 演进必然漂移。配套 CI UP/DOWN 配对校验、`security.md` "DB rollbackSchema <5min" 承诺一并退役。

## Decision

- **ADR-012**：删除零消费者代码/配置/部署面；unleash 卸载；密码策略 `registerSchema.password` 由 `min(6)` 提升至 `min(12)`；RBAC 维持静态矩阵 + JWT（保留 `user_roles`/`role_permissions` 表结构）；事件收敛为单一 outbox 路径（Run 聚合根与 `BacktestCompletedHandler` 一并退役，worker 直接 `persistRunIfTenant → save()`）；quota 删除 60s 窗口，仅保留标的数校验（422）、月度 gate（402）与计量；burst 由 computeLimiter 兜底。
- **ADR-013**：新增迁移 004/005 删除死 schema；基线 001 同步收敛移除 `idx_users_mfa_enabled` 创建与 `password_changed_at` 空操作；RLS 策略改为 `NULLIF(current_setting(...), '')` 转义空字符串。
- **ADR-014**：从请求契约删除 `riskFreeRate`（optimizeSchema / efficientFrontierSchema）与 `withReplacement`（monteCarloSchema.mcParams）；前端移除对应 UI 开关与请求字段；Go 引擎不改动。
- **ADR-015**：删除 `data-fetcher/cmd/worker/` 全部 8 个文件；配套测试随子系统退役删除。
- **ADR-016**：删除 `handleApiKeyAuth` / `handleOptionalApiKey` / `verifyPayload` / `deleteUser`；配套测试迁移到被包装的真实函数；用户删除统一走匿名化路径。
- **ADR-017**：删除 `verify-backend.mjs` 与 `verify-frontend.mjs`；`run-all.mjs` 移除 `--skip-db/--skip-frontend`；`ci.yml` 改 `pnpm verify:critical` 全量执行；`_lib.mjs` 移除 `loadPg` / `withDb`；C-005/C-006 断言迁移至既有 E2E spec。
- **ADR-018**：迁移管理改为 forward-only；删除 `rollbackSchema` 与 7 个 down 文件；`check-migrations.mjs` 收敛为 up-only 校验；DB 回滚口径改为备份恢复（`scripts/backup-restore.sh`）；`security.md` 同步收敛；配套测试迁移（删除两个 rollback 场景 + 两个 rollbackSchema 单测）。
- 删除门禁按决策原则统一执行：确认零消费者、无悬挂配置面、测试迁移、各 ADR 独立提交。

## Consequences

- (+) 消除死配置面、死 schema、死脚本与重复路径，减少维护/误配风险。
- (+) API 契约只保留引擎真实实现的能力，消除误导性配置面。
- (+) 迁移路径单一（forward-only），符合行业标准与可审计性；DB 回滚由备份恢复统一承载。
- (+) 密码策略从"看似可配、实际未生效"变为真实强制；用户删除统一走匿名化路径。
- (-) 未来启用动态 RBAC / 功能开关 / CAGG / 可配置无风险利率 / 无放回抽样 / 代码级 schema 降级，需以本 ADR 为基线重新引入（成本显式可见）。
- (-) DB 状态类验证不再由独立脚本覆盖；RLS/迁移由集成测试与静态检查承担。
