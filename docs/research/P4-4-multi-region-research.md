# P4-4: 多区域部署架构评估报告

> 生成日期：2026-07-26 | 状态：纯调研报告 | 决策建议：**GA 后按用户地理分布评估，当前单区域足够**

## 1. 背景

B2C 平台面向中国和全球用户（中英双语界面），中国大陆用户访问海外服务延迟高（200-400ms RTT）。需评估多区域部署的必要性和成本。

## 2. 用户地理分布分析

### 2.1 数据采集方法

| 数据源                    | 方法                             | 可行性      |
| ------------------------- | -------------------------------- | ----------- |
| Nginx/APISIX 访问日志     | 按 `X-Forwarded-For` IP 地理定位 | ✅ 当前可用 |
| Cloudflare Analytics      | 按 country code 统计             | 需接入 CDN  |
| Google Analytics          | 前端埋点                         | 需集成 GA4  |
| 前端 `navigator.language` | 语言偏好统计                     | ✅ 当前可用 |

### 2.2 预期分布（基于双语界面推断）

| 区域     | 预期占比 | RTT 到美东 | RTT 到新加坡 | RTT 到上海 |
| -------- | -------- | ---------- | ------------ | ---------- |
| 中国大陆 | 40-60%   | 200-400ms  | 50-100ms     | 10-30ms    |
| 东南亚   | 10-20%   | 180-250ms  | 20-50ms      | 50-100ms   |
| 北美     | 15-25%   | 10-30ms    | 150-200ms    | 200-400ms  |
| 欧洲     | 5-10%    | 80-120ms   | 180-250ms    | 250-350ms  |

## 3. 数据合规性

### 3.1 A 股数据跨境传输

| 数据类型              | 合规要求                                     | 影响                  |
| --------------------- | -------------------------------------------- | --------------------- |
| 历史价格数据（OHLCV） | 可能属于"金融数据"，需评估《数据安全法》分类 | 需法律咨询            |
| 用户持仓数据          | 个人信息（《个人信息保护法》）               | 需用户同意+数据本地化 |
| 交易/回测结果         | 可能属于衍生数据                             | 需评估                |

### 3.2 建议合规策略

1. **数据分层**：公开历史价格数据可全球缓存；用户数据须区域化存储
2. **写入中心化**：所有写操作走单一主区域（数据一致性）
3. **读副本区域化**：用户数据在用户所在区域只读副本
4. **法律咨询**：GA 前聘请数据合规律师评估 A 股数据出境合规性

## 4. 部署方案对比

### 方案 A：CDN + 单一 API 区域

```
用户 → Cloudflare CDN（静态资源） → 单一 API 区域（美东/上海）
                                     → PostgreSQL（主库）
                                     → Redis（缓存）
```

| 维度     | 评价                                    |
| -------- | --------------------------------------- |
| 延迟改善 | 静态资源：全球 <50ms；API 仍受 RTT 影响 |
| 成本     | 低（仅 CDN 费用）                       |
| 复杂度   | 最低                                    |
| 合规     | 用户数据集中存储，需区域化策略          |

### 方案 B：多区域 API + 共享数据库

```
用户 → 区域 API（上海/美东） → PostgreSQL 跨区域只读副本
                                ↓（写入）
                             主库（单一写入点）
```

| 维度     | 评价                              |
| -------- | --------------------------------- |
| 延迟改善 | API 延迟降至 10-50ms（区域内）    |
| 成本     | 中（多区域计算 + 跨区域 PG 复制） |
| 复杂度   | 中（只读/读写路由、复制延迟处理） |
| 合规     | 用户数据可在各区域只读副本        |

### 方案 C：完全独立部署

```
上海区域：完整栈（API + DB + Redis + Engine）
美东区域：完整栈（API + DB + Redis + Engine）
定期数据同步（CDC / 批量导出导入）
```

| 维度     | 评价                     |
| -------- | ------------------------ |
| 延迟改善 | 所有操作区域内完成       |
| 成本     | 高（双倍基础设施）       |
| 复杂度   | 高（数据同步、冲突解决） |
| 合规     | 数据物理隔离，合规最佳   |

### 方案 D：Cloudflare Workers 边缘计算

```
用户 → Cloudflare Worker（边缘，全球 300+ 节点）
  → 只读 API（D1/KV 缓存）
  → 写入代理到单一主区域
```

| 维度     | 评价                         |
| -------- | ---------------------------- |
| 延迟改善 | 读操作全球 <50ms             |
| 成本     | 低（Workers 按请求计费）     |
| 复杂度   | 中（Worker 逻辑 + 缓存失效） |
| 合规     | 数据在边缘缓存，需评估       |

## 5. 成本估算（月度，GA 后）

| 方案            | 计算成本 | 数据库成本       | 缓存成本 | 网络成本 | 合计/月 |
| --------------- | -------- | ---------------- | -------- | -------- | ------- |
| A（CDN+单区域） | $200     | $100             | $50      | $30      | ~$380   |
| B（多区域 API） | $400     | $300（只读副本） | $100     | $80      | ~$880   |
| C（完全独立）   | $800     | $600             | $200     | $50      | ~$1,650 |
| D（Workers）    | $50      | $100             | $30      | $20      | ~$200   |

## 6. 决策建议

### **GA 后按用户分布评估，当前单区域足够**

**理由**：

1. 内测阶段无付费用户，延迟 200-400ms 可接受
2. 多区域部署成本高（$880-$1650/月），ROI 不合理
3. 数据合规需法律咨询，不宜过早投入
4. CDN 方案（方案 A）成本最低且可渐进升级

### 推进路径

1. **GA 前**：接入 Cloudflare CDN（方案 A），改善静态资源全球延迟
2. **GA 后 3 个月**：分析用户地理分布，若中国大陆 > 40% 则评估方案 B
3. **GA 后 6 个月**：若需数据本地化合规，评估方案 C 或法律咨询
