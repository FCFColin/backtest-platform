# Break-Glass 密钥操作规程（P0-04 / 等保三级）

## 使用条件

- 何时: 所有按组织 API 密钥均不可用/吊销, 需紧急平台管理
- 谁可使用: 经技术负责人授权的运维人员
- 为何: 必须声明使用目的, 记录到审计日志

## 密钥生命周期

| 操作     | 流程                                               |
| -------- | -------------------------------------------------- |
| 首次部署 | 生成 ADMIN_API_KEY, 存入 K8s Secret, 记录审计      |
| 轮换     | 生成新密钥 -> 部署 -> 确认新密钥生效 -> 吊销旧密钥 |
| 吊销     | 从 K8s Secret 移除, 标记审计日志, 通知所有运维     |
| 列表     | GET /api/v1/admin/keys (requirePlatformAdmin)      |

## 审计与监控

- 每次 break-glass 密钥使用自动记录审计日志(userId, timestamp, action, ip)
- AlertManager 告警: break-glass 密钥使用时触发 P1 告警通知安全负责人
- 定期审查: 每季度检查 break-glass 密钥使用记录

## 故障处置

| 场景             | 处置                                                      |
| ---------------- | --------------------------------------------------------- |
| 所有平台密钥吊销 | 从 K8s Secret 恢复或重新生成 ADMIN_API_KEY                |
| Redis 不可用     | 认证 fail-closed 503, break-glass 密钥也无法使用(ADR-018) |
| 数据库不可用     | API Key 存储在 PG, break-glass 通过 K8s Secret 独立可用   |
