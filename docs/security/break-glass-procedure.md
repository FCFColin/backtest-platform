# Break-Glass 密钥操作规程（P0-04 / 等保三级）

## 使用条件

所有按组织 API 密钥均不可用/吊销时使用；仅经技术负责人授权的运维人员；必须声明目的并记录审计。

## 密钥生命周期

| 操作     | 流程                                          |
| -------- | --------------------------------------------- |
| 首次部署 | 生成 ADMIN_API_KEY → K8s Secret → 记录审计    |
| 轮换     | 新密钥 → 部署 → 确认生效 → 吊销旧密钥         |
| 吊销     | Secret 移除 + 审计标记 + 通知运维             |
| 列表     | GET /api/v1/admin/keys (requirePlatformAdmin) |

## 审计与监控

每次使用自动记审计（userId, timestamp, action, ip）；AlertManager P1 告警通知安全负责人；每季度审查使用记录。

## 故障处置

| 场景             | 处置                                                  |
| ---------------- | ----------------------------------------------------- |
| 所有平台密钥吊销 | 从 K8s Secret 恢复或重新生成                          |
| Redis 不可用     | 认证 fail-closed 503, break-glass 亦不可用（ADR-018） |
| 数据库不可用     | API Key 存 PG, break-glass 经 K8s Secret 独立可用     |

等保: 8.1.3.1 访问控制(特权用户) + 8.1.4.1 身份鉴别(应急认证)。
